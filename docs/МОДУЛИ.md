# Описание модулей — HeadHunter

Подробное описание каждого модуля проекта для продолжения разработки.

---

## Frontend (`src/`)

### `src/main.jsx`
Точка входа React-приложения. Монтирует корневой компонент в DOM, подключает глобальный CSS.

---

### `src/App.jsx`
Центральный файл всего приложения. Содержит:
- **Провайдеры:** `ErrorBoundary` → `AuthProvider` → `NotificationProvider` → `QueryClientProvider` → `BrowserRouter`
- **Все маршруты** — несколько сотен `<Route>`, разбитых по ролям/тенантам
- **Глобальные контейнеры:** `ModalContainer`, `DrawerContainer`, `ToastContainer`

Именно здесь можно найти все существующие маршруты и что они рендерят.

---

### `src/lib/`

#### `AuthContext.jsx`
- Загружает публичные настройки приложения из Base44
- Валидирует токен авторизации
- Тянет `base44.auth.me()` — текущего пользователя
- Загружает `Organization` по `user.organization_id`
- Экспортирует контекст: `user`, `organization`, `isAgency`, `isCompany`, `isSuperAdmin`, `login`, `logout`

#### `ProtectedRoute.jsx`
- Обёртка маршрута с проверкой авторизации
- Проверяет: `requiredRole`, `requiredOrgType`, суперадмин обходит все проверки
- Незавершённые/неразрешённые → через `RoleFallback`

#### `RoleFallback.jsx`
- Для аутентифицированных пользователей — редирект на домашнюю страницу роли
- Для гостей — показывает 404

#### `permissions.js`
Клиентская матрица разрешений. Каждая роль получает объект разрешений на чтение/запись/удаление по сущностям.  
Три scope уровня:
- `own` — только свои записи
- `team` — записи своей команды
- `agency` — все записи организации

Используется через `usePermission` / `usePermissionMatrix` хуки.

#### `aiMatching.js`
Правиловый движок матчинга (без API-вызовов, работает на клиенте):
- Принимает кандидата и вакансию
- Считает взвешенный score 0–100 по: домену, роли, специализации, навыкам (soft+hard), опыту, локации, зарплате
- Используется в `AIMatchingPage`, карточках вакансий, CRM

#### `pipelineNotifications.js`
Создаёт уведомления (entity `Notification`) при смене стадии кандидата в пайплайне.

#### `roleAliasResolver.js`
Преобразует alias роли в отображаемое название.

#### `query-client.js`
Синглтон `QueryClient` для React Query. Конфигурация кеширования.

#### `errors/`
- `AppError.ts` — кастомный класс ошибки
- `errorNormalizer.ts` — нормализует любые ошибки в `AppError`
- `useErrorHandler.ts` — хук для обработки ошибок в компонентах

#### `dialogs/`
Zustand-подобный стор для открытия/закрытия глобальных модалок и drawer'ов.

#### `notifications/`
Стор уведомлений — хранит список, добавляет/удаляет.

### `src/hooks/`

#### `useCandidateCRM.js` ⭐
Главный хук CRM-раздела. Принимает `candidateId`, возвращает полный набор данных:
- Профиль кандидата
- Заявки (applications)
- Заметки (notes)
- Документы (documents)
- Интервью (interviews)
- Таймлайн
- Теги
Использует ленивую загрузку (подгружает дополнительные данные по требованию) и кеширование через React Query.

#### `usePipelineData.js` ⭐
Данные для ATS канбан-доски:
- Загружает `Application` entities с фильтрами
- Метод `moveCard(applicationId, newStatus)` — обновляет статус заявки
- Fallback на mock-данные при ошибке
- Поддержка фильтров: по вакансии, рекрутеру, периоду

#### `usePermission.jsx` / `usePermissionMatrix.js`
Хуки для проверки разрешений в компонентах.  
Пример: `const canEdit = usePermission('candidate', 'update')`.

#### `useAdminStats.js`
Агрегирует статистику для дашборда администратора: количество кандидатов, вакансий, заявок, конверсия.

#### `useCandidateList.js`
Пагинированный список кандидатов с фильтрами и сортировкой. Учитывает роль пользователя для RLS.

#### `useDataTable.ts`
Универсальный хук для таблиц: пагинация, сортировка, выбор строк.

#### `useModal.ts` / `useDrawer.ts`
Управление состоянием глобальных модалок и drawer'ов.

#### `use-mobile.jsx`
Определяет мобильный viewport для адаптивной вёрстки.

### `src/api/` (инфраструктура, частично используется)

> Этот слой спроектирован для постепенной миграции от прямых вызовов `base44.entities` к сервисному паттерну.

#### `base44Client.js`
Создаёт клиент Base44 SDK из `appParams`.

#### `client/httpClient.ts`
Axios-обёртка с:
- Кешом GET-запросов (in-memory)
- Retry логикой
- Редиректом на логин при 401

#### `repositories/baseRepository.ts`
Дженерик CRUD поверх REST `/api/*`. Методы: `list`, `get`, `create`, `update`, `delete`, `filter`.

#### `services/candidateService.ts`
Репозиторий кандидата + хелперы: поиск, загрузка резюме.

#### `services/jobService.ts`
Репозиторий вакансии + методы: закрыть, репостнуть, обновить счётчик просмотров.

#### `services/applicationService.ts`
Репозиторий заявки + методы: обновить статус, получить score.

## Backend (`base44/`)

### `base44/entities/` (40 схем)

JSONC-файлы, каждый описывает:
- Поля (тип, обязательность, default)
- RLS правила (read/write/delete по роли и полям)
- Индексы
- Связи

### `base44/functions/` (62 Deno функции)

Каждая функция — это папка с `index.ts` или `handler.ts`. Запускаются через `base44.functions.{name}.invoke(params)` с клиента или внутренними вызовами.

Группы функций:

**Email intake:**
- `emailIntakeHandler/` — главный обработчик входящих писем с CV на `+{job_code}@`
- `emailPoolIntakeHandler/` — общий пул (`+pool@`)
- `verifyPoolIntake/` — верификация email

**Разбор резюме:**
- `extractAndTranslateResume/` — LLM-извлечение и перевод
- `analyzeResume/` — анализ резюме
- `parseResumeBatch/` — батч-парсинг
- `extractResumeFieldConfidence/` — уверенность по каждому полю
- `convertResumeToDocx/` — конвертация в DOCX

**Импорт:**
- `importCandidatesFromFile/` — старт импорта из файла
- `processCandidateImport/` — обработка одной записи
- `importQueueProcessor/` — очередь импорта
- `importRetryQueue/` — повторные попытки
- `validateImportBatch/` — валидация батча
- `handleImportError/` — обработка ошибок
- `createBulkCandidates/` — массовое создание

**Внешние источники:**
- `importAlljobs/`, `importJobicy/`, `importWix/`, `importNvidia/`, `importElbit/`, `importNovolog/`, `importShafir/` — импорт вакансий
- `crawlCareerPage/` — краулинг карьерной страницы

**AI:**
- `scoreApplication/` — LLM-оценка заявки vs вакансия
- `getJobRecommendations/`, `getRecommendedJobs/` — рекомендации
- `smartSearch/` — умный поиск
- `enrichJobDescriptions/` — обогащение описаний

**Безопасность:**
- `checkPermission/`, `checkInternalPermission/` — серверная проверка разрешений
- `validateEntityOwnership/` — проверка владельца
- `verifyHierarchyIsolation/` — изоляция иерархии
- `createAuditLog/` — запись аудита
- `auditDuplicateDetection/`, `auditPoolMerges/`

**Дубликаты:**
- `detectDuplicateAdvanced/` — умный поиск дублей кандидатов
- `separateFalseMerges/` — разделение ложно объединённых

**Таймлайн/уведомления:**
- `createCandidateTimeline/`, `createApplicationTimeline/` — события таймлайна
- `createCompanyNotification/` — уведомление компании
- `sendInterviewReminder/` — напоминание об интервью
- `sendJobAlerts/` — email-алерты по вакансиям
- `sendCandidateToEmployer/` — отправка профиля клиенту

**Операционные:**
- `getDashboardStats/` — статистика дашборда
- `generateJobCode/` — генерация уникального кода вакансии
- `generateSitemaps/` — SEO карты сайта
- `deleteCandidate/` — мягкое/жёсткое удаление
- `checkSlaBreaches/` — проверка нарушений SLA
- `loadTaxonomy/` — загрузка справочников
- `resolveRoleFromAlias/` — определение роли по алиасу
- `migrateUsersToOrg/` — миграция пользователей

**Debug:**
- `debugEmailHeaders/`, `debugGmailSearch/`, `debugCVExtraction/`, `verifyPhaseA/`, `getLocationFromIP/`
