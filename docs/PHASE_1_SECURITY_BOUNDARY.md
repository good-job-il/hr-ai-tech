# Phase 1 security and external dependency boundary

Verified: 13 August 2026.

## Code boundary

- Runtime source contains no request or asset URL under `*.base44.com`.
- Application branding uses repository-owned files under `public/`; `public/logo.png` is required by the CI gate.
- CSP restricts `connect-src` to the application origin, the production API, any additional origin configured by `VITE_API_BASE_URL`, and local development HTTP/WebSocket endpoints. Images are limited to the application origin, `data:`, `blob:` and the explicitly retained `images.unsplash.com` host.
- Unsupported provider login controls and `loginWithProvider` are absent.
- The compatibility shim no longer exports `asServiceRole`.
- The browser cannot submit arbitrary email recipient/subject/body data. `/integrations/send-email`, `SendEmailDto` and `integrations.Core.SendEmail` have been removed.
- Application-submitted and interview-scheduled mail is generated by explicit backend domain events after the authorized record is saved.
- Mock email mode does not log the recipient or message body.
- External migration tooling is disabled unless the operator passes `--allow-legacy-network` after data-owner approval.

Run:

```bash
npm run release:verify
```

The same check runs in `.github/workflows/legacy-api-boundary.yml`.

## Credential and data-migration status

The ignored local `backend/.env` still contains configured migration credentials (values were not printed or copied). No repository evidence proves that production reconciliation and cutover were signed off. Therefore Codex did not delete the credentials or claim that they were revoked.

Required production-owner actions:

1. Record source/target row counts and exception reconciliation for every migrated entity.
2. Confirm the final delta migration and application cutover time.
3. Assign a named production data owner and security owner in the release ticket.
4. Revoke the external API key/token and reset the migration account password in the provider console.
5. Remove all `BASE44_*` lines from every active local, CI and deployment secret store.
6. Re-run `npm run release:verify` and the browser smoke suite used by the deployment environment.

Credential revocation is an external action and cannot be inferred from a successful code build.

## Remaining proof

The static network boundary is enforced. A browser E2E run with DNS/proxy blocking for `*.base44.com` still requires a running seeded environment and role credentials. Until that run and credential revocation are recorded, Phase 1 is code-complete but not operationally signed off.
