# React Hooks: безопасная проверка зависимостей

`npm run lint:hooks` проверяет `rules-of-hooks` и `exhaustive-deps` во всём `src` независимо от остальных lint-проблем. Нарушения считаются ошибками также в обычных `lint` и `lint:fix`.

`npm run lint:fix` не исправляет массивы зависимостей автоматически: добавление функции или объекта может изменить частоту запросов либо вызвать цикл. Dangerous autofix явно выключен. Это не автоматическое подавление предупреждений — исправление требует проверки смысла эффекта.

## Как исправлять новые случаи

1. Если эффект действительно зависит от значения — добавить его в зависимости.
2. Если значение вычисляется из props/state — вычислять при рендере или через `useMemo`, а не синхронизировать второй state эффектом.
3. Если запрос использует callback — перенести функцию внутрь эффекта либо стабилизировать через `useCallback` с полными зависимостями.
4. Если callback читает state только для обновления — использовать функциональный setter. Не включать изменяемый номер страницы в эффект первичной загрузки: передавать страницу явным аргументом.
5. Отделять ключ загрузки (например, ID кандидата) от зависимостей локального пересчёта (актуальный кандидат и загруженные вакансии).
6. Для асинхронных эффектов игнорировать устаревший ответ или отменять запрос при cleanup.
7. Не удалять массив зависимостей и не отключать правило ради зелёного lint.

`npm run test:hooks` проверяет строгость правил, отсутствие опасного autofix, все исходники и регрессии инициализации формы/пагинации. Статические тесты не заменяют UI-проверку запросов, переключения workspace и ручных правок.

Официальное руководство: [Removing Effect Dependencies](https://react.dev/learn/removing-effect-dependencies).
