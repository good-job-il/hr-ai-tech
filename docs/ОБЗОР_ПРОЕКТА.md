## Что это такое

**HeadHunter** — это HR-tech платформа для израильского рынка труда. Это не просто доска вакансий — это полноценная экосистема, включающая:

- **ATS (Applicant Tracking System)** — канбан-доска для ведения кандидатов
- **CRM для кандидатов** — история, заметки, документы, таймлайн
- **Мультиарендная архитектура** — кадровые агентства и HR-отделы компаний работают в одной системе но в разных пространствах
- **Автоматический импорт CV** — по email, из файлов, со сторонних job-сайтов
- **AI-матчинг** — автоматическое сопоставление кандидатов с вакансиями
- **Публичная витрина** — сайт с вакансиями и профилями компаний для соискателей

## Архитектура данных

Нет традиционной SQL-базы. Всё хранится в **40 Base44 entities** — это JSONC-схемы в `base44/entities/`.

### Поток данных

```
React страница/компонент
        ↓↑
Custom Hook (useQuery / useCandidateCRM / usePipelineData)
        ↓↑
base44.entities.*  — CRUD операции (главный путь)
base44.functions.* — вызов serverless функций (AI, импорт, email)
base44.auth.*      — авторизация
        ↓↑
Base44 Backend (Deno + Entity Store + RLS)
```

> **Важно:** В `src/api/` есть слой репозиториев (`candidateService`, `jobService`), но страницы в основном ещё используют `base44.entities` напрямую. Миграция на этот слой запланирована но не завершена.

## Мультиарендность (Multi-tenancy)

Каждая сущность содержит `organization_id`. Тип организации (`org_type`) определяет доступные маршруты:

| Тип (`org_type`) | Маршруты | Описание |
|------------------|----------|----------|
| `staffing_agency` | `/agency/*` | Кадровое агентство |
| `organization` | `/company/*` | HR-отдел компании |
| — (platform) | `/platform/*` | Оператор платформы |
| — (legacy) | `/employer/*` | Старый путь (в процессе миграции) |

## Ключевые модули

### `src/lib/AuthContext.jsx`
Загружает публичные настройки Base44, валидирует токен, тянет `base44.auth.me()`, определяет `isAgency` / `isCompany` / `isSuperAdmin`. Вся логика авторизации централизована здесь.

### `src/lib/ProtectedRoute.jsx`
Охраняет маршруты по роли и типу организации. Super-admin обходит все проверки. Незнакомые маршруты перенаправляются через `RoleFallback`.

### `src/lib/permissions.js`
Клиентская матрица разрешений по ролям — кто что видит и редактирует. Три уровня scope: своё / команда / агентство.

### `src/lib/aiMatching.js`
Клиентский движок AI-матчинга. Правиловая система (0–100 баллов) с весовыми коэффициентами по:
- Домен / роль / специализация
- Навыки (soft/hard)
- Опыт
- Локация
- Зарплатные ожидания

### `src/hooks/useCandidateCRM.js`
Главный хук CRM. Подгружает всё по кандидату: заметки, интервью, документы, заявки, таймлайн — с ленивой загрузкой и кешированием.

### `src/hooks/usePipelineData.js`
Данные для канбан-доски: заявки, перемещение по стадиям, фильтры, fallback на mock-данные.

### `src/lib/pipelineNotifications.js`
Создаёт уведомления при смене стадии в пайплайне.

### `src/config/navigation/`
- `agencyNav.js` — меню для кадровых агентств
- `companyNav.js` — меню для корпоративного HR
- `platformNav.js` — меню суперадмина

## База данных (40 entities)

### Ядро

| Entity | Назначение |
|--------|-----------|
| `User` | Пользователь: роль, `organization_id`, иерархические ID |
| `Organization` | Тенант: тип, план, статус подписки |
| `Candidate` | CRM-карточка кандидата: профиль, навыки, URL резюме, владелец |
| `CandidateProfile` | Самостоятельный профиль соискателя (по email) |
| `Job` | Вакансия: таксономия, зарплата, `job_code`, `apply_email` |
| `Application` | Заявка кандидата на вакансию: статус, match score, источник |
| `Company` | Справочник компаний-работодателей |
| `Interview` | Запланированные интервью |

### CRM / ATS поддержка

`CandidateNote`, `CandidateTag`, `CandidateDocument`, `CandidateTimeline`, `CandidateAccess`, `CandidateImportBatch`, `ApplicationTimeline`, `ApplicationPipeline`, `JobTimeline`, `CommunicationLog`, `CompensationPlan`, `Position`, `Staff`

### Таксономия (справочники)

`Domain`, `Role`, `RoleAlias`, `RoleTemplate`, `Specialization`, `ExperienceLevel`, `EmploymentType`, `WorkMode`

### Системные

`PermissionMatrix`, `AuditLog`, `Notification`, `Message`, `SavedJob`, `JobAlert`, `SalaryData`, `ImportSource`

### Ключевые связи

```
Organization
  ├── Users (с ролями)
  ├── Jobs
  ├── Candidates
  └── Applications (job_id + candidate_id)

Candidate ──→ Applications ──→ Job
           ├── Documents, Notes, Tags, Timeline
           └── Interviews

Job ──→ job_code ──→ email-алиас для приёма CV
```

### RLS (Row-Level Security)

Каждая entity определяет правила `rls.create/read/update/delete`. Проверяются:
- `user.role`
- `data.organization_id === user.organization_id`
- Поля владения: `recruiter_id`, `team_manager_id`, `recruitment_manager_id`

## Серверные функции (62 Deno функции)

### Приём CV по email
`emailIntakeHandler` — входящее письмо на `+{job_code}@gmail.com` → скачивает CV → LLM парсит → проверка дублей → создаёт Candidate + Application + Document + Timeline

`emailPoolIntakeHandler` — входящее письмо на `+pool@gmail.com` → кандидат попадает в общий пул без привязки к вакансии

### Импорт
`importCandidatesFromFile`, `importResumeFiles`, `processCandidateImport`, `importQueueProcessor`, `validateImportBatch`, `createBulkCandidates` — полный пайплайн массового импорта кандидатов

### Внешние источники вакансий
`importAlljobs`, `importJobicy`, `importWix`, `importNvidia`, `importElbit`, `importNovolog`, `importShafir`, `crawlCareerPage` — автоматический краулинг/импорт вакансий

### AI / Матчинг
`scoreApplication` — LLM оценивает заявку vs вакансия, записывает `match_score` и `match_reason`

`getJobRecommendations`, `getRecommendedJobs`, `smartSearch`, `enrichJobDescriptions`

### Безопасность и аудит
`checkPermission`, `checkInternalPermission`, `validateEntityOwnership`, `verifyHierarchyIsolation`, `createAuditLog`, `auditDuplicateDetection`

### Уведомления и коммуникации

## Бизнес-логика (пользовательские сценарии)

### A. Соискатель (candidate)

1. Заходит на `/` — маркетинговый лендинг (иврит, RTL)
2. Ищет вакансии на `/jobs` — фильтры, AI-бейджи совпадения
3. Открывает `/jobs/:id` — детальная вакансия
4. Подаёт заявку → форма + загрузка CV → создаётся `Application`
5. Регистрируется → `/candidate/dashboard` *(многие подстраницы ещё placeholder)*

### B. Кадровое агентство

**Путь:** `/agency/*` | Роли: `org_admin`, `recruitment_manager`, `team_manager`, `recruiter`

1. **Управление вакансиями** — `/agency/jobs` → создать/редактировать вакансию, автоматический `job_code` + email-алиас
2. **Приём CV** — кандидаты шлют CV на `+{job_code}@gmail.com` или `+pool@gmail.com`, backend автоматически создаёт сущности
3. **CRM** — `/agency/crm` → список кандидатов; клик → полный CRM (заметки, таймлайн, документы, отправка клиенту)
4. **Пайплайн (ATS)** — `/agency/pipeline` → канбан по стадиям; drag-and-drop обновляет `Application.status`
5. **AI-матчинг** — `/agency/ai-matching` → оценка кандидатов по открытым вакансиям
6. **Импорт** — `/agency/import` → массовый импорт CSV/ZIP с резюме
7. **Компенсации** — `/agency/compensation` → планы выплат рекрутерам

### C. Корпоративный HR

**Путь:** `/company/*` | Роли: `org_admin`, `hr_manager`, `internal_recruiter`

Аналогично агентству, но для внутреннего найма:
- Управление собственными вакансиями
- Просмотр кандидатов, CRM
- AI-матчинг
- Команда/интервью/аналитика — частично placeholder

### D. Суперадмин (платформа)

**Путь:** `/platform/*` | Роли: `admin`, `super_admin`

- Управление всеми организациями
- Подписки, инвойсы, маркетплейс
- Системная аналитика, журнал аудита
- Шаблоны ролей и разрешений
